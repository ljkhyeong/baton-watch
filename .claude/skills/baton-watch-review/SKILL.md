# BATON WATCH 변경 검토

대상: $ARGUMENTS

대상이 비어 있으면 작업 시작 커밋 기준 전체 변경(`git diff <작업 시작 커밋> --`)과 새 파일(`git ls-files --others --exclude-standard`)을 본다.
PR 번호면 `gh pr diff <번호>`와 `gh pr view <번호>`로 읽는다. diff만 보지 말고 바뀐 메서드의 호출자와 관련 테스트도 읽는다.

## 확인 항목

위험이 큰 순서다. 해당 영역이 바뀐 경우만 확인한다.

1. **외부 요청 안전성**: 스킴·포트·자격 증명·모호한 호스트·대체 IP 표기 거부, 리다이렉트마다 재검증, DNS 결과 전체 검증과 검증한 IP 고정, 원래 Host·TLS 검증 유지. 대상 GET 본문 미소비, 콜백 리다이렉트 금지. 시간·헤더·바이트·동시성·큐 상한 유지. 세부는 [외부 통신](../baton-watch-outbound-http/SKILL.md) 스킬.
2. **민감 정보**: 응답·로그·예외 메시지·메트릭에 URL 원문·쿼리·토큰·쿠키·인가 헤더·응답 본문·해석된 IP·원인 예외가 들어가지 않는지 확인한다. 설정 오류와 테스트 실패 메시지도 포함한다.
3. **트랜잭션과 리스**: 점유·완료가 짧은 별도 트랜잭션인지, DNS·HTTP가 트랜잭션 밖인지 확인한다. 완료가 리스·원본 리비전으로 오래된 결과를 막는지, 같은 완료 요청을 중복 처리하지 않는지, `SKIP LOCKED`·원자적 SQL 조건이 유지되는지 본다.
4. **이벤트 전달**: 상태 변경과 이벤트 삽입이 같은 트랜잭션인지, 상태가 같으면 이벤트를 만들지 않는지 확인한다. 페이로드 불변, 상한 있는 지수 백오프, 미전달 이벤트 보존, 보존 기간이 지난 전달 완료 행만 삭제하는지도 본다.
5. **시간**: `Instant.now()`·`System.currentTimeMillis()` 대신 주입한 `Clock`과 UTC를 쓰는지, 시간 경계 테스트가 고정 `Clock`을 쓰는지 확인한다.
6. **계층**: `bootstrap → adapters → application → domain` 방향, 어댑터 간 직접 의존 금지, 웹 진입점의 입력 포트 사용. 도메인·애플리케이션에 Spring·JDBC·HTTP 타입이 들어오지 않는지 확인한다.
7. **마이그레이션과 권한**: 적용된 마이그레이션을 수정하지 않았는지(보존 데이터가 없어 V1을 직접 고친 경우는 ADR-0002·HANDOFF에 볼륨 재생성 안내가 있는지), 새 테이블·열의 런타임 권한이 최소인지, 매핑의 null 허용·제약이 SQL과 맞는지 확인한다.
8. **메트릭 레이블**: URL·호스트·IP·리소스 참조·이벤트 ID·예외 메시지처럼 값의 종류가 계속 늘어나는 레이블이 없는지 확인한다. 이름·의미가 바뀌었으면 경보·대시보드 쿼리도 바뀌었는지 본다.
9. **중복과 범위**: 같은 경계의 중복 검증, 수동 구현한 프레임워크 기능, 요청과 무관한 변경이 있는지 본다. 서로 다른 경계의 검증을 “중복”으로 지우지 않았는지도 확인한다.
10. **테스트와 문서**: 수정 전 실패를 재현하는 테스트가 있는지, 건너뛴 DB 테스트가 없는지 확인한다. 계약 변경이 PRD에, 설정·동작 변경이 README에, 검증 결과가 HANDOFF에 반영됐는지와 `docs/PRD`·`docs/ADR` 링크 대소문자도 본다.

## 결과 작성

- 심각도 순으로 `파일:줄`, 문제 한 문장, 실패 시나리오(입력·상태 → 잘못된 결과), 제안을 쓴다.
- 코드로 확인한 사실과 추정을 구분한다. 추정은 확인 방법을 함께 적는다.
- 발견이 없으면 “발견 없음”과 확인한 범위·확인하지 못한 범위를 적는다.
- PR에 댓글을 남기는 것은 외부 게시이므로 사용자가 요청하거나 승인한 경우에만 한다.
- 자체 검토에서 찾은 문제는 고친 뒤 해당 검사를 다시 실행한다.
