# PRD-0001: BATON WATCH 제품 범위

상태: 유지 관리 문서

수정일: 2026-09-08

## 목적

BATON WATCH는 BATON `RoleResource`에 등록된 URL의 연결 상태를 점검하는 독립 서비스다.
BATON의 데이터 변경·조회가 점검을 기다리지 않도록, BATON 커밋 이후 별도로 실행해야 한다.

## 현재 기능

PRD-0003의 URL 점검과 PRD-0004의 상태 변경 전달을 구현했다.

- 리비전과 활성 여부가 포함된 URL 스냅샷을 받아 자원 제한 안에서 비동기로 점검한다.
- 점검 시도·결과를 DB에 저장하고 현재 상태를 계산한다. 상태가 바뀌면 이벤트도 저장한다.
- 설정한 BATON HTTPS 콜백 하나로 이벤트를 전달한다. DB에 저장한 리스로 작업을 점유하고,
  재시도로 최소 한 번 전달을 보장하며 전달 완료 이벤트에는 보존 기간을 적용한다.
- 로그·메트릭을 제공하며 메트릭 레이블 값의 종류를 제한한다.

운영 배포는 완료하지 않았다.

인스턴스 시작 시 점검 예약만 끄는 설정과 리소스별 점검·전달 이력의 제한된
읽기 전용 운영 CLI도 제공한다. 유지보수와 별도로 활성화한 이벤트 전달은 점검
중지 중에도 계속된다. 인증된 수동 재점검 예약 API는 기존 일정을 앞당기거나
대기·실행 중인 점검을 재사용하고 리소스별 30초 간격을 적용한다. 전체 점검의 실시간
중지·재개 API와 최종 사용자용 이력 조회 API는 제공하지 않는다.

BATON 최신 불변 아웃박스를 읽기 전용 SQL로 내보내고 WATCH와 대조하는 복구 도구를 제공한다.
기본 실행은 조회만 하며, 검토한 파일의 SHA-256을 지정한 재전송 모드에서 같은 리비전과
원래 본문으로 누락·낮은 리비전의 모니터를 복구한다. 더 높은 원격 리비전이나 본문 충돌은
자동으로 덮어쓰지 않는다. [독립 복원 절차](../../runbooks/baton-snapshot-recovery.md)를 따른다.

대상 GET은 응답 헤더로 도달 여부를 판단한 뒤 본문을 읽지 않고 연결을 닫는다.
큰 본문 크기만으로 장애를 판정하지 않으며, 본문 전체 다운로드나 로그인 뒤 콘텐츠의
접근성을 보장하지 않는다. 콜백 전달은 기존 본문 제한을 유지한다.

스테이징 터널에는 NGINX의 경로별 요청 속도 제한을 제공하고, Compose는 Spring Boot의
기본 준비 상태와 DB 상태를 확인한다. 기존 메트릭용 Grafana JSON 템플릿도 제공한다.
설정 파일 제공과 실제 가동은 구분한다. 공개 배포·수집기·대시보드 서버·외부 알림의 가동 여부는 별도로 확인해야 한다.
별도의 Blackbox Exporter 모듈과 Prometheus 수집·경보 템플릿으로 내부 프록시 및
공개 HTTPS 요청 경로를 확인할 수 있다. WATCH 자체의 고정 상태 경로만 대상으로
하며 RoleResource 검사나 BATON 콜백 전달을 대체하지 않는다. 실제 적용은 운영 승인 후다.

## 담당 범위

WATCH는 다음을 관리한다.

- BATON이 제공한 리소스 참조별 비동기 URL 점검 일정
- 점검 시도·결과 이력: 보존 기간을 적용하고 저장 후 수정하지 않음
- 점검 결과로 판단한 상태: UNKNOWN, HEALTHY, DEGRADED 또는 BROKEN
- 상태가 변경될 때만 DB에 저장하는 이벤트
- 설정한 BATON 콜백으로 이벤트를 비동기로 최소 한 번 전달하는 기능

PRD-0003은 모니터링 MVP를 위한 최초의 일정, 재시도, 상태, 보존,
인증 및 HTTP 검사 계약을 채택한다. PRD-0004는 이벤트 전달을 위한 직접
HTTPS 콜백, 페이로드, 인증, 멱등성, 재시도/리스, 보존, 안전 및 관측성
계약을 채택한다.

## 제외 범위

WATCH는 절대로 다음을 수행해서는 안 된다.

- BATON 워크스페이스·역할·리소스의 접근 권한 판단
- RoleResource 내용과 접근 권한의 원본 데이터 관리
- 응답 본문, 자격 증명, 쿠키 또는 인가 헤더 저장
- BATON의 데이터 변경·조회 트랜잭션이 URL 점검을 기다리게 함

자료와 접근 권한은 BATON이 관리한다. WATCH 결과가 없거나 오래되었다는 이유만으로 BATON 접근을 거부해서는 안 된다.

## 작업 처리와 트랜잭션

검사 워커는 각 항목을 처리하기 직전에 짧은 트랜잭션에서 한 건씩 선점한 뒤
트랜잭션을 종료하고 대상 요청을 수행해야 한다. 이후 별도의 짧은 트랜잭션에서
점검 시도·결과와 상태 변경 이벤트를 DB에 저장해야 한다. 이벤트 디스패처도 별도의 콜백
POST 전후로 같은 트랜잭션 경계를 따른다. 리스는 만료 시간이 있는 작업 점유이며,
멱등성은 같은 완료 요청을 반복해도 중복 처리하지 않는 성질이다. 두 작업 모두 이 규칙을
사용하고, 배치 허용 실행 시간을 종료 대기보다 짧게 제한해 중단된 작업을 다시 처리할 수 있게 한다. 시간에 의존하는
모든 결정에는 주입된 `Clock`과 UTC 시각을 사용한다.

## 외부 HTTP 요청 안전 기준

검사기는 연결하기 전에 다음을 수행해야 한다.

1. 채택된 스킴과 포트만 허용한다.
2. 포함된 자격 증명이나 모호한 대체 IP 형식을 허용하지 않고 호스트를 파싱하고 정규화한다.
3. DNS를 조회하고 루프백, 링크 로컬, 사설, 멀티캐스트, 미지정, 메타데이터 및 그 밖의 비공개 목적지를 거부한다.
4. 올바른 HTTP 호스트와 TLS 검증을 유지하면서 검증된 조회 결과 집합의 주소에만 연결한다.
5. 대상 검사에서는 리디렉션마다 전체 정책을 다시 적용하고 리디렉션 횟수를 제한하며, 이벤트 전달에서는 리디렉션을 거부한다.
6. 연결 시간, 읽기 시간, 전체 시간, 응답 바이트 및 동시성을 제한한다.

이 정책은 DNS 리바인딩과 검증 시점부터 연결 시점까지 발생하는 변경을 고려해야 한다. 응답 본문은 절대로 영속화하지 않는다. 로그에서는 URL의 사용자 정보, 쿼리 및 프래그먼트를 가려야 한다. 메트릭에는 제한된 식별자나 결과 클래스만 사용하고 원시 URL, 호스트, 리소스 ID 또는 예외 메시지를 레이블로 사용해서는 안 된다.

## 상태 의미

UNKNOWN은 현재 상태를 판단할 유효한 점검 결과가 없음을 뜻한다.
HEALTHY, DEGRADED, BROKEN은 점검 결과와 연속 실패 횟수로 판단한다. PRD-0003은 MVP
임계값과 리디렉션, TLS, DNS, 타임아웃 및 내부 실패 처리 방식을 정의한다.

## 이벤트 전달 의미

상태 변경 이벤트는 최소 한 번 전달되므로 BATON은 `Idempotency-Key`와 JSON `eventId`가
일치하는지 확인하고, 처리한 `eventId`를 DB에 기록해 중복 처리를 막아야 한다. 콜백은
별도의 Bearer 서비스 토큰과 제한된 페이로드를 사용하며, 대상 URL, 응답 본문,
자격 증명 또는 인가 결정을 포함하지 않는다. WATCH는 전달되지 않은 모든
이벤트를 보존하고 제한된 보존 작업을 통해 전달 완료 이벤트만 삭제한다.
전체 계약은 PRD-0004를 기준으로 한다.
